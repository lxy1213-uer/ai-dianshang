# 外部服务接入手册

六项外部依赖的**本地骨架已全部完成**：协议、默认实现、配置入口、假客户端测试都在仓库里。
本文只讲「拿到真实资源后怎么接 + 怎么验收」。未配置任何外部资源时，默认零配置演示行为不变。

配合阅读：[`.env.example`](../.env.example) 列出了全部变量；[`README.md`](../README.md) 是总体设计。

## 0. 本地替身环境（零账号、零公网、一键起）

六项外部依赖都可以在本机 Docker 里跑替身，不需要申请任何账号或密钥，也不产生真实资金流转。
替身只负责「像真服务一样通信」，应用侧代码与真实接入完全一致。

**启动顺序**

```bash
# 1) 起替身（Docker Compose v2 支持 --wait；老版本去掉该参数）
docker compose -f docker-compose.local.yml up -d --wait

# 2) 安装两个可选驱动（其余四项是纯标准库，无需装包）
pip install -r requirements.txt -r requirements-local.txt

# 3) 首次拉 embedding 模型
docker compose -f docker-compose.local.yml exec ollama ollama pull nomic-embed-text

# 4) 自检
python scripts/local_stubs/check_local_env.py

# 5) 用本地替身配置启动应用（不改 .env；LLM 密钥等原有环境变量照常生效）
python scripts/local_stubs/run_local_app.py
# Windows PowerShell 等价命令：
#   .\scripts\local_stubs\run_local.ps1
```

> 若想把替身参数固化进 `.env`：先 `python scripts/local_stubs/apply_local_env.py` 预览，
> 确认后加 `--apply` 写入；原文件会备份为 `.env.bak.local`。

**替身清单**

| 依赖 | 容器 | 端口 | 本地账号/密钥 |
|---|---|---|---|
| OIDC IdP | Keycloak 26 | 8080 | `agent01/boss01/viewer01/admin01`，密码均 `pwd`，realm `ecom-agent` |
| Redis | redis:7 | 6379 | 无密码 |
| 企微 webhook | webhook-sink | 8081 | `AGENT_WECOM_WEBHOOK=http://127.0.0.1:8081/webhook` |
| Postgres | postgres:16 | 5432 | `ecom_agent / ecom_agent / ecom_agent` |
| Embedding | Ollama | 11434 | `nomic-embed-text`，OpenAI 兼容 `/v1/embeddings` |
| 支付网关 | payment-gateway | 8082 | API secret `local-api-secret`，回调 secret `local-callback-secret` |

**六项快速验收**

1. OIDC：取 token 并登录（注意本地是 http，JWKS 地址必须在 `.env` 显式给出）
   ```bash
   TOKEN=$(python scripts/local_stubs/get_keycloak_token.py | tail -1)
   curl -s -X POST http://127.0.0.1:8000/api/auth/login \
     -H 'Content-Type: application/json' \
     -d "{\"username\":\"agent01\",\"password\":\"$TOKEN\"}"
   curl -s http://127.0.0.1:8000/api/health | grep oidc_configured
   ```
2. Redis：`curl -s http://127.0.0.1:8000/api/health | grep rate_limit_backend` 应为 `redis`；
   同一 IP 连续打 `/api/chat` 超过 60 次应返回 429 + `Retry-After`。
3. 企微：`curl -s http://127.0.0.1:8081/messages` 应能看到脱敏后的 markdown 通知（先触发 `/api/desk/sla-check`）。
4. Postgres：`curl -s http://127.0.0.1:8000/api/health | grep lock_backend` 应为 `pg`。
5. Embedding：`curl -s http://127.0.0.1:8000/api/health | grep embedding_configured` 应为 `true`；
   语义相关但字面不命中的问句应能改变引用排序。
6. 支付网关（正确签名 / 篡改 / 重放 / 对账）：
   ```bash
   # 正确回调：应 200 且 requires_manual_review=true
   curl -s -X POST http://127.0.0.1:8082/__local/send-callback \
     -H 'Content-Type: application/json' \
     -d '{"refund_id":"RFD-DEMO","ticket_id":"T-DEMO","status":"SUCCESS","amount":99.5}'
   # 负向用例：把 tamper 改成 body / timestamp / signature / replay，应拿到 401
   # 对账：导出的 CSV 上传后只输出差异建议，不改任何状态
   curl -s http://127.0.0.1:8082/ledger.csv > ledger.csv
   curl -s -X POST -H 'Content-Type: text/csv' --data-binary @ledger.csv \
     'http://127.0.0.1:8000/api/refund/reconcile?format=auto'
   ```

**边界**：替身容器里的日志写在命名卷 `stub-data`；`down` 不会删卷，重启后仍可查历史通知/回调。
Keycloak 的 `iss` 必须与 `AGENT_OIDC_ISSUER` 完全一致，镜像已用 `KC_HOSTNAME_URL` 固定为 `http://localhost:8080`。

## 0.5 无 Docker 的真实协议联调（零依赖一键跑）

若本机没有 Docker / 无法安装驱动，还有一条**真实网络 I/O**的联调路径：用纯标准库
在 `127.0.0.1` 上起六项最小协议服务，让**项目里的真实客户端代码**（不是假对象）
通过真实 socket 连上去。签名、验签、SQL、并发锁都是真的，只有「服务端不是厂商产品」。

```bash
# 1) 一键起六项替身（打印端口与 .env 配置片段）
python scripts/local_stubs/run_integration.py

# 2) 另一终端跑联调测试（18 项：客户端协议级 14 + 应用端点级 4）
python -m pytest tests/test_external_integration.py tests/test_app_integration.py -q
```

**六项联调覆盖**

| 依赖 | 协议 | 真实客户端 | 验证点 |
|---|---|---|---|
| OIDC | HTTP JWKS + RS256 | `HttpJwksSource` / `verify_id_token` / `OidcIdentityProvider` | 真签发 token → HTTP 拉 JWKS → 验签 → 登录换会话 token；篡改 401 |
| Redis | RESP over TCP | `RedisLimiter` + `pipeline/zset/pexpire` | 滑动窗口 3 次放行第 4 次拒绝；两实例共享计数 |
| 企微 webhook | HTTP POST | `WecomNotifier` | `errcode=0` 判定、失败重试、发送前 PII 脱敏 |
| 支付网关 | HTTP + HMAC | `HttpRefundGateway` / `RefundCallbackVerifier` / `parse_ledger` | 幂等退款、错签 401、回调重放 401、对账差异只给建议 |
| Embedding | OpenAI `/v1/embeddings` | `HttpEmbeddingClient` / `EmbeddingReranker` | 真向量改变 Top-K 顺序；服务故障降级 BM25 |
| Postgres | SQL 语义（%s→?） | `PgLeaseSessionLocker` + 真 socket | `ON CONFLICT` 租约互斥、只释放自己的 owner |

**与 Docker 方案的分工（诚实边界）**

- 本节方案用来验证**客户端代码与协议的正确性**：快、可进 CI、不需要任何安装；
- Postgres 这一项是 **SQL 语义级联调**，不是 pg wire 协议级——真要验证 `psycopg` 驱动、
  连接串、`TIMESTAMPTZ` 行为，仍必须用第 0 节的 Postgres 16 容器；
- Redis 替身验证的是 `RedisLimiter` + RESP 协议（测试中直接注入适配器）。若把
  `AGENT_RATE_LIMIT_BACKEND=redis` 写进 `.env` 让**应用**使用，仍需先 `pip install redis`：
  应用的 `build_limiter` 走 redis-py，未安装时会回退内存限流而非连到替身；
- 生产接入请把 `.env` 指向厂商真实端点，客户端代码一行都不用改。

## 1. 真实 IdP / SSO（OIDC）

**代码**：`app/oidc.py`（验签）、`app/identity.py::OidcIdentityProvider`（身份源）、`app/config.py::oidc_*`

**需要**：一个 OIDC IdP（企业微信/Auth0/Keycloak/自建），拿到 issuer、client_id、client_secret。

**步骤**

1. 在 IdP 注册应用，回调地址指向你的前端（不是本后端）；授权方式选 Authorization Code + PKCE。
2. 前端完成登录、拿到 `id_token`（JWT）。
3. 后端 `.env`：
   ```
   AGENT_IDP_PROVIDER=oidc
   AGENT_OIDC_ISSUER=https://your-idp.example.com
   AGENT_OIDC_AUDIENCE=your-client-id
   AGENT_OIDC_JWKS_URL=                    # 留空走 <issuer>/.well-known/openid-configuration
   AGENT_AUTH_SECRET=<随机长字符串>        # 本系统签发自己 token 的密钥，与 IdP 无关
   ```
4. 前端登录请求把 `id_token` 放进 `/api/auth/login` 的 `password` 字段；服务端验 `iss/aud/exp/nbf` + RS256 签名后，用 JWT 的 `sub` 作为 `user_id`、`role`/`app_role` 作为坐席角色（缺省 viewer）。

**验收**

```bash
python -m pytest -q tests/test_external_idp.py     # 16 项：假 IdP 签发/验签/拒绝路径
curl /api/health | grep oidc_configured             # 应为 true
```
手工：拿一个真 token 登录应 200；把 token 改一个字符、过期 token、错误 audience 都应 401。

**边界**：只接受 RS256；`role` 是可选 claim，最终权限仍由 `AGENT_RBAC_ENABLED` + 角色表决定；JWKS 缓存 300 秒（换密钥需重启或等待过期）。

## 2. Redis 多实例限流

**代码**：`app/ratelimit.py::RedisLimiter`、`build_limiter()`

**需要**：Redis 实例（本地 `docker run -d -p 6379:6379 redis` 或云 Redis）。

**步骤**

```bash
pip install redis                    # 唯一需要装的可选依赖
```
```
AGENT_RATE_LIMIT_BACKEND=redis
AGENT_REDIS_URL=redis://127.0.0.1:6379/0
AGENT_RATE_LIMIT_PER_MIN=60          # 关键：默认 0 是关闭，必须设非零
AGENT_RATE_LIMIT_CHAT=0              # 0=跟随全局；可给单接口设更小值
```

**验收**

```bash
python -m pytest -q tests/test_pluggable_backends.py    # 假 Redis 客户端验证原子滑窗
curl -i -X POST /api/chat ...                          # 超限返回 429 + Retry-After
curl /api/health | grep rate_limit_backend              # 应为 redis
```
手工：开两个 uvicorn worker，连续打同一 IP，两个实例的计数应共享（第 61 次 429）。

**边界**：连接失败时回退进程内限流（可用性优先）——生产要把这个 warning 接监控；`client_ip` 不信任 `X-Forwarded-For`，反代需自行改写或在可信网关终止。

## 4. Postgres（持久化 + 分布式锁）

**代码**：`app/pglock.py::PgLeaseSessionLocker`、`app/locking.py::build_session_locker()`

**需要**：Postgres 实例。

**步骤**

最小改法（**只把锁切到 Postgres，主库仍 SQLite**）：

```bash
pip install 'psycopg[binary]'
```
```
AGENT_LOCK_BACKEND=pg
AGENT_PG_DSN=postgresql://user:pass@localhost:5432/ecom_agent
AGENT_LOCK_LEASE_SECONDS=30          # LLM 单轮可达 69s，按实际调大
```
锁表 DDL 在 `app/pglock.py::PG_LOCK_DDL`（`TIMESTAMPTZ`），首次连接自动建表。

要整体迁库：把 `app/db.py` 的 `SCHEMA` 中 `?` → `%s`、`AUTOINCREMENT` → `IDENTITY`、`TEXT` 时间列 → `TIMESTAMPTZ`，连接换成 psycopg；`SessionLocker` 协议与 `Coordinator` 不用改。

**验收**

```bash
python -m pytest -q tests/test_external_pglock.py tests/test_locking.py
curl /api/health | grep lock_backend    # 应为 pg
```
手工：起两个实例并发打同一 session，只有一个能进入；杀掉持锁进程，等 lease 到期后另一个应能接管。

**边界**：显式配 `pg` 但缺驱动会**直接报错**（不静默退回进程内锁，否则多实例串行化被破坏）；租约依赖时钟，跨机器需 NTP。

## 6. 支付网关（回调验签 + 对账）

**代码**：`app/settlement.py`、`app/refund.py::HttpRefundGateway`、`app/main.py` 两个端点

**需要**：支付网关的退款 API URL、API secret、回调 secret。

**步骤**

```
AGENT_REFUND_API_URL=https://gateway.example.com/refunds
AGENT_REFUND_API_SECRET=<请求签名密钥>
AGENT_REFUND_CALLBACK_SECRET=<回调验签密钥>
AGENT_REFUND_CALLBACK_TOLERANCE=300
```

**回调接入**：网关配回调地址 `POST https://your-host/api/refund/callback`。签名口径：
```
signature = HMAC-SHA256(callback_secret, timestamp + "." + raw_body)
请求头 X-Refund-Signature: <hex>
请求头 X-Refund-Timestamp: <unix 秒>
```
body 形如 `{"refund_id":"RFD-1","ticket_id":"T-1","status":"SUCCESS","amount":99.5}`。
验签通过**只落事件、返回 `requires_manual_review: true`**——绝不自动推进工单状态或再次打款。

**对账**：从网关下载对账 CSV/JSON，上传：
```bash
curl -X POST -H 'X-Staff-Token: <supervisor token>' \
     -H 'Content-Type: text/csv' \
     --data-binary @gateway_settlement.csv \
     'https://your-host/api/refund/reconcile?format=auto'
```
返回四类差异：`local_only` / `gateway_only` / `status_mismatch` / `amount_mismatch`，每条带 `suggested_action`。**只输出建议，不改任何状态**。

**验收**

```bash
python -m pytest -q tests/test_external_settlement.py tests/test_refund.py
```
手工：构造正确签名回调应 200 且 `requires_manual_review`；篡改 body/时间戳/签名应 401；重复回调第二次应 401（幂等去重）；上传含差异的 CSV 应列出对应 kind。

**边界**：回调与对账都不自动改状态——资金类补救必须人工复核；退款仍是非事务链路（网关成功 → SUCCESS 流水 → 推进状态），状态推进失败记 `refund_status_failed` 事件；金额由调用方传入，不产生真实资金流转直到接上真实网关。

## 7. 订单源接入（离线 CSV / 真实订单 API）

售后判断要落到真实买家订单，只需换订单源；核单、资格判定、状态机、工单和诊断层都不改。默认 `AGENT_ORDER_SOURCE=json` 继续读 `app/data/orders.json`，零配置行为不变。

**方式 A：离线 CSV（不需要开放平台权限）**

平台导出的表格直接接进来，示例表头见 `app/data/orders_douyin_sample.csv`：

```bash
python scripts/import_orders.py --input app/data/orders_douyin_sample.csv --dry-run
python scripts/import_orders.py --input app/data/orders_douyin_sample.csv --output data/orders_imported.json
ORDERS_PATH=data/orders_imported.json python -m uvicorn app.main:app --reload
# 或直接读 CSV，不生成中间 JSON：
AGENT_ORDER_SOURCE=csv AGENT_ORDER_SOURCE_PATH=app/data/orders_douyin_sample.csv python -m uvicorn app.main:app --reload
```

默认表头：`order_no / buyer_id / product_name / pay_amount / order_status / sign_time`；完整别名与状态映射见 `app/domain/order_sources.py`。表头不同就用 `AGENT_ORDER_SOURCE_FIELD_MAP` 覆盖，例如：

```bash
AGENT_ORDER_SOURCE_FIELD_MAP='{"order_id":"订单编号","user_id":"买家账号","title":"商品名称","amount":"实付金额","status":"订单状态","signed_at":"签收时间"}'
```

**方式 B：真实 API（抖店/开放平台拿到权限后）**

```bash
AGENT_ORDER_SOURCE=http
AGENT_ORDER_SOURCE_URL=https://your-gateway.example.com/orders
AGENT_ORDER_SOURCE_TOKEN=<服务端保存的 token>
AGENT_ORDER_SOURCE_FIELD_MAP='{"order_id":"out_order_no","user_id":"buyer_open_id","title":"goods_name","amount":"pay_amount","status":"order_status","signed_at":"receive_time"}'
```

接口需返回订单数组，或 `{"orders":[...]}` / `{"data":[...]}` / `{"items":[...]}` / `{"list":[...]}`。字段映射不齐、状态无法识别或 `user_id` 缺失时整批拒绝，不会猜用户、不会把未知状态当成已签收。真实接入时 `buyer_open_id` 必须先在本系统映射为登录身份 `user_id`（用 OIDC `sub` 或账号表），否则所有订单都会因归属不匹配而不可见——这是刻意的。

**验收**

```bash
curl -s 'http://127.0.0.1:8000/api/orders?user_id=u_1001' | python -m json.tool
curl -s http://127.0.0.1:8000/api/health | grep order_source_detail
python -m pytest -q tests/test_order_sources.py tests/test_order_api.py
```

诊断页 `/diagnose` 会自动加载「我的订单」下拉框；选中订单后生成的诊断带真实订单事实与条款证据。外部源失败时接口返回 503 + `order_source_unavailable`，不会说成「查不到这个订单」。
